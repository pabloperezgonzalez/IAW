### 1. Introducción
Existen muchos **gestores de contenidos (CMS)** y cada uno presenta unas características diferentes. Antes de instalar un CMS debemos analizar aspectos como:

- Su finalidad y uso.
- Tipo de licencia.
- Coste.
- Requisitos técnicos.
- Facilidad de administración.
- Posibilidades de personalización.
- Seguridad.
- Extensiones disponibles.
- Comunidad y soporte.

El objetivo es poder **comparar diferentes CMS y seleccionar el más adecuado para cada proyecto**.

### 2. Uso y finalidad
El primer aspecto que debemos analizar es **para qué queremos utilizar el CMS**. No es lo mismo crear un blog que una tienda online o una plataforma educativa.

| Necesidad | CMS que podría utilizarse |
|---|---|
| Blog | WordPress |
| Web corporativa | WordPress, Joomla, Drupal |
| Tienda online | PrestaShop |
| Plataforma educativa | Moodle |
| Wiki | MediaWiki |
| Portal de contenidos | Drupal |

> La elección debe comenzar siempre por las **necesidades del proyecto**, no por el CMS que conozcamos mejor.

### 3. Licencia del CMS
La **licencia** determina las condiciones bajo las cuales podemos utilizar, modificar y distribuir el software. Muchos CMS utilizan licencias de software libre o de código abierto. Algunas licencias habituales son:

- **GPL** (General Public License): Exige que cualquier obra derivada o código modificado que use este software se distribuya también bajo la misma licencia GPL. El código permanece libre obligatoriamente. No permite cerrar el código en proyectos comerciales derivados.
- **MIT**: Permite casi cualquier uso, incluidos el comercial y el propietario, con restricciones mínimas. Solo exige conservar el aviso de autoría (copyright) original y la exención de responsabilidad.
- **Apache License**: Similar a MIT, pero incluye cláusulas explícitas sobre patentes y el uso de marcas registradas. Otorga derechos de patente de los creadores a los usuarios y prohíbe usar marcas de los autores originales en trabajos derivados.

Debemos diferenciar entre: **Código abierto ≠ necesariamente gratuito en todos sus componentes**
Un CMS puede ser gratuito y, al mismo tiempo, utilizar extensiones, temas o servicios comerciales.

### 4. Coste
El coste de un CMS no depende únicamente de si podemos descargarlo gratuitamente. Por tanto, debemos valorar el **coste total de la solución**, considerando:

- Licencia del CMS.
- Hosting o servidor.
- Dominio.
- Certificados.
- Temas o plantillas.
- Plugins o extensiones.
- Soporte técnico.
- Mantenimiento.
- Copias de seguridad.

> Por ejemplo: **CMS gratuito → Hosting + dominio + mantenimiento + extensiones**

### 5. Requisitos técnicos
Antes de instalar un CMS debemos comprobar que el servidor cumple sus requisitos. Podemos necesitar:

- Sistema operativo compatible.
- Servidor Web.
- Versión determinada de PHP u otro lenguaje.
- Sistema gestor de bases de datos.
- Espacio de almacenamiento.
- Memoria RAM.
- Extensiones del lenguaje.
- Certificado TLS.

> Por ejemplo: **CMS → Servidor Web + PHP + SGBD + extensiones**

### 6. Facilidad de uso y administración
Otro aspecto importante es la facilidad con la que los usuarios y administradores pueden utilizar el CMS. Debemos valorar:

- Interfaz de administración.
- Gestión de contenidos.
- Gestión de usuarios.
- Configuración.
- Actualizaciones.
- Copias de seguridad.
- Instalación de extensiones.

Un CMS sencillo puede ser adecuado para una pequeña Web, mientras que un proyecto más complejo puede necesitar una plataforma con mayores posibilidades de administración.

### 7. Personalización y extensiones
Los CMS suelen permitir ampliar sus funcionalidades mediante:

- Plugins.
- Módulos.
- Componentes.
- Temas.
- Plantillas.
- Extensiones.

> Por ejemplo: **CMS → Extensión de comercio electrónico → Productos + Carrito + Pedidos**

Antes de seleccionar un CMS debemos comprobar si existen extensiones suficientes para cubrir las necesidades del proyecto. También debemos valorar su calidad, mantenimiento y compatibilidad con la versión utilizada.

---

### 8. Seguridad y mantenimiento

La seguridad es especialmente importante cuando el CMS está conectado a Internet.

Debemos valorar:

- Frecuencia de actualizaciones.
- Rapidez en la corrección de vulnerabilidades.
- Seguridad del núcleo.
- Seguridad de plugins y extensiones.
- Gestión de usuarios y permisos.
- Copias de seguridad.
- Comunidad de desarrolladores.

Un CMS abandonado o con extensiones sin mantenimiento puede suponer un riesgo para el servidor.

> No basta con elegir un CMS popular. También debemos comprobar que pueda mantenerse **actualizado y seguro**.

### 10. Resumen
Para diferenciar las características de los gestores de contenidos debemos analizar diferentes aspectos:

| Aspecto | Qué debemos valorar |
|---|---|
| Uso | Finalidad del CMS |
| Licencia | Condiciones de utilización y modificación |
| Coste | CMS, hosting, extensiones y mantenimiento |
| Requisitos | Servidor, lenguaje, SGBD y recursos |
| Administración | Facilidad de configuración y gestión |
| Personalización | Temas, plugins y extensiones |
| Seguridad | Actualizaciones y protección |
| Comunidad | Soporte y documentación |
| Mantenimiento | Actualizaciones, copias y soporte |

El proceso de selección puede resumirse en: **Necesidades → Comparación → Requisitos → Coste → Seguridad → Selección del CMS**

#### Idea clave
> Antes de instalar un gestor de contenidos debemos **conocer y comparar sus características**. La elección debe basarse en el uso que tendrá, su licencia, coste, requisitos técnicos, posibilidades de personalización, seguridad y mantenimiento. El CMS más adecuado será aquel que proporcione las funcionalidades necesarias con un coste y una complejidad razonables.
